# 制造领航团队分工与协作方案

## 1. 分工原则

团队按4条可独立验收的技术主线分工，而不是简单地把页面、接口和AI割裂开：

1. 每个人都有明确的主责模块、代码和测试；
2. Stitch设计与前端工程实现分开，设计由项目负责人统一，React实现由前端负责人完成；
3. 数据库是事实来源，RAG是文档证据来源，Agent只负责受控编排，三者不能互相替代；
4. Issue #4“诊断Agent与工单闭环”是共同集成任务，不归某一个人包办；
5. 所有模块通过接口契约、Pull Request和自动测试连接。

> `Fabric-devc` 已接受仓库邀请并拥有 `write` 权限，其具体角色在确认个人技术偏好后填入下表。其余成员GitHub账号待补充。

## 1.1 AI辅助开发约定

项目鼓励所有成员使用AI完成需求拆解、代码脚手架、测试生成、调试、文档和设计探索，但“使用AI开发”不等于“无需理解代码”。每个PR作者仍对提交内容负责：

- 能解释核心数据结构、接口和算法；
- 亲自运行测试并记录真实结果；
- 检查AI生成代码的权限、异常、并发和数据泄露风险；
- 不向模型上传API Key、真实企业资料和未脱敏设备数据；
- 不把模型输出直接作为关键设备事实或高风险维修指令；
- PR中说明重要的AI辅助范围及人工验证方式。

比赛展示重点不是“我们用AI把代码写出来了”，而是产品本身具备可验证的AI能力：带证据的RAG、受控Agent工具调用、参数来源与冲突处理、人工确认和维护业务闭环。

| RAG与检索评测 | 队员C（待填） | PDF解析、分块、索引、混合检索、引用、模型适配与评测 | 文档管线、检索API、评测集、准确性报告 |

## 3. 详细职责

### 3.1 项目负责人：产品、Stitch、Agent与总集成

负责：

- 明确目标用户、比赛范围和演示故事；
- 使用Stitch完成设备中心、诊断工作台、工单和看板设计；
- 输出颜色、字体、间距、组件状态和响应式规则；
- 定义Agent可调用的工具、输入输出和失败回退；
- 维护跨模块接口清单和里程碑；
- 审核PR是否符合产品、数据安全和比赛要求；
- 负责最终部署、录屏、答辩和材料一致性。

不负责：

- 包办全部React页面；
- 绕过数据库直接把关键设备参数写进Prompt；
- 在其他成员没有测试的情况下替其合并代码。

必须交付：

- Stitch设计链接、导出截图和设计规范；
- `Agent Tool Contract`：每个工具的名称、参数、返回值和错误；
- 端到端演示脚本；
- 每周集成验收记录。

### 3.2 队员A：React前端工程

负责：

- 建立React + TypeScript项目结构；
- 将Stitch设计转换为可维护组件，不直接复制一次性HTML；
- 实现设备列表、设备档案、诊断工作台、工单和看板；
- 统一API客户端、加载/空/错误/权限状态；
- 为核心交互编写组件或端到端测试；
- 输出响应式截图和演示录屏。

必须交付：

- 前端运行说明；
- 共享组件和页面路由；
- API类型定义；
- 关键页面测试；
- 与Stitch设计差异说明。

主Issue：[#2 Web诊断工作台](https://github.com/lxiaotian685-web/forgepilot-ai/issues/2)

建议分支：`feature/web-diagnostic-workbench`

### 3.3 队员B：数据库与FastAPI后端

负责：

- 设计企业、工厂、产线、设备、部件、参数、工单、备件和审计模型；
- 使用PostgreSQL和迁移工具管理结构变更；
- 实现登录、角色权限和企业数据隔离；
- 实现设备档案、参数、工单与历史记录API；
- 保证外键、唯一约束、状态约束和事务一致性；
- 编写API和数据库测试。

必须交付：

- ER图和字段字典；
- 可重复执行的数据库迁移；
- OpenAPI接口；
- 虚构或脱敏种子数据；
- 权限隔离和关键约束测试。

主Issue：[#1 设备数据库](https://github.com/lxiaotian685-web/forgepilot-ai/issues/1)

建议分支：`feature/equipment-database`

### 3.4 队员C：RAG与检索评测

负责：

- 解析PDF说明书和维修规范；
- 设计文档、页码、分块、版本和设备型号关联；
- 实现向量与关键词混合检索及可选Rerank；
- 返回文件、页码、引用片段和检索分数；
- 建立问题、标准答案、证据位置和评分方法组成的评测集；
- 处理无答案、文档冲突和模型不可用场景。

必须交付：

- 文档入库命令或接口；
- 检索接口与来源引用；
- 至少20条评测问题；
- 命中率、引用准确率和无答案测试结果；
- 一份虚构或已脱敏的演示文档集。

主Issue：[#3 说明书RAG](https://github.com/lxiaotian685-web/forgepilot-ai/issues/3)

建议分支：`feature/equipment-rag`

## 4. Agent闭环的共同分工

Issue [#4 诊断Agent与维护工单闭环](https://github.com/lxiaotian685-web/forgepilot-ai/issues/4)按下面的责任矩阵完成：

| 子任务 | 主责 | 配合 | 验收结果 |
|---|---|---|---|
| Agent状态和工具编排 | 项目负责人 | 队员B、C | 能查看每一步工具调用与结果 |
| 诊断工作台交互 | 队员A | 项目负责人 | 支持提问、过程状态、证据和人工确认 |
| 设备参数查询工具 | 队员B | 项目负责人 | 只返回当前企业有权访问的结构化数据 |
| 文档检索工具 | 队员C | 项目负责人 | 返回可验证的文档、页码和片段 |
| 工单创建与状态流转 | 队员B | 队员A | 用户确认后创建，过程可审计 |
| 工单前端与结果回写 | 队员A | 队员B | 能完成指派、处理、关闭和回看 |
| 安全规则和失败回退 | 项目负责人 | 全员 | 高风险建议不自动执行，失败不伪造结果 |
| 端到端测试 | 全员 | 项目负责人汇总 | 完整演示流程稳定通过 |

## 5. 模块接口边界

### 前端依赖

前端只依赖OpenAPI和Mock数据，不直接读取数据库。后端接口未完成时，使用与OpenAPI相同结构的Mock响应开发。

### 数据库与RAG边界

- 型号、额定功率、序列号等关键设备参数来自结构化数据库；
- 操作步骤、故障解释和安全规范来自带证据的文档检索；
- RAG不得静默覆盖数据库关键参数；
- 发生冲突时同时展示两种来源并要求人工确认。

### Agent边界

Agent只能调用已注册工具，不直接执行SQL，不直接修改设备和工单。写操作必须经过权限校验和用户确认。

## 6. PR审查关系

| PR类型 | 必须审查的人 | 重点 |
|---|---|---|
| Stitch/产品/Agent | 至少1名相关模块成员 | 可实现性、业务闭环、安全边界 |
| React前端 | 项目负责人；涉及接口时加队员B | 设计还原、状态覆盖、接口一致性 |
| 数据库/后端 | 项目负责人；涉及RAG时加队员C | 数据模型、权限、迁移、兼容性 |
| RAG/模型 | 项目负责人；涉及数据结构时加队员B | 证据、评测、无答案、成本 |
| 跨模块集成 | 全员查看，至少1人批准 | 端到端流程和回归风险 |

PR必须包含：关联Issue、改动说明、测试命令与结果；UI改动提供截图，API改动提供示例，数据库改动提供迁移和回退方式。

## 7. 里程碑与交付

### 第1周：契约与骨架

- 项目负责人：Stitch核心页面、Agent工具清单、API草案；
- 队员A：React工程、路由、Mock设备列表与诊断页面；
- 队员B：ER图、PostgreSQL、迁移和设备模型；
- 队员C：PDF解析、分块模型和最小检索实验。

### 第2周：三条主线可独立运行

- 前端可用Mock完成核心演示；
- 后端完成设备CRUD与权限骨架；
- RAG可对演示说明书返回来源；
- 项目负责人完成第一版Agent编排。

### 第3周：诊断转工单闭环

- 前后端接入真实接口；
- Agent同时调用数据库与RAG；
- 用户确认后生成工单；
- 完成第一轮端到端测试。

### 第4周：质量、部署与比赛材料

- 修复错误、权限和响应式问题；
- 完成评测、测试报告、部署和监控；
- 准备录屏、架构图、ER图、分工证据和答辩稿。

## 8. 完成标准 Definition of Done

一个任务只有同时满足以下条件才能关闭：

- 功能达到Issue验收标准；
- 自动测试通过；
- 相关文档更新；
- 没有密钥和未经授权的企业数据；
- API、数据库或UI变更提供对应证据；
- 至少一名非作者完成PR审查；
- 已在集成环境验证，不只是作者电脑可运行。

## 9. 每周协作节奏

- 周初：确认本周Issue、负责人和依赖；
- 开发中：每个分支保持短小，每1至2天推送一次；
- PR前：作者自行运行测试并更新说明；
- 周中：完成一次接口或页面联调；
- 周末：全员跑一次完整演示，记录问题与下周计划。

任何阻塞超过半天，应在Issue中说明，不要等到周会才提出。
