# 制造领航 ForgePilot 项目方案

## 1. 项目定位

制造领航是一套面向中小制造企业的设备知识、智能诊断和维护协同平台。系统以设备主数据和维修业务数据库为底座，以RAG知识库提供可追溯证据，通过Agent编排设备查询、文档检索、故障分析、工单与备件工具。

## 2. 目标用户

- 设备维修与点检人员；
- 车间班组长；
- 设备主管；
- 工艺与质量工程师；
- 缺少专职数字化团队的中小制造企业。

## 3. 核心问题

- 设备说明书、故障记录和员工经验分散；
- 新人排查故障依赖老师傅；
- 维修过程和结果没有形成结构化知识；
- 工单、备件和设备档案之间缺少关联；
- 普通大模型回答无法证明来源，可能产生危险建议。

## 4. 核心模块

### 设备资产中心

- 工厂、产线、设备与部件层级；
- 设备型号、序列号、关键参数和状态；
- 二维码快速进入设备档案；
- 说明书、图片、点检表和历史工单关联。

### RAG知识库

- PDF说明书和维修规范解析；
- 文档分块、向量与关键词混合检索；
- 回答展示文档、页码和引用片段；
- 不同设备型号和企业空间的数据隔离。

### 诊断 Agent

- 识别用户意图和设备上下文；
- 调用设备数据库、知识库、历史故障和备件工具；
- 生成分步骤检查建议；
- 区分已知事实、推断和待确认信息；
- 涉及安全风险时强制提示人工确认。

### 维护工单

- 从诊断结果创建工单；
- 指派人员、状态流转、处理记录和图片；
- 关联故障代码、根因、措施和使用备件；
- 完成后沉淀为可检索案例。

### 数据分析

- 设备故障频次和停机时间；
- 常见故障与根因；
- 维修响应时间和完成率；
- 备件消耗与缺货风险；
- RAG命中率和AI建议采纳情况。

## 5. 数据库建议

- `organizations`、`users`、`memberships`；
- `factories`、`production_lines`；
- `equipment`、`components`、`equipment_parameters`；
- `documents`、`document_chunks`；
- `fault_codes`、`diagnosis_sessions`、`agent_runs`、`tool_calls`；
- `work_orders`、`work_order_events`、`maintenance_records`；
- `spare_parts`、`inventory_transactions`；
- `evidence_links`、`audit_logs`。

数据库设计需要体现多租户隔离、状态约束、外键完整性、参数来源和审计记录。

## 6. 技术架构

- 前端：React + TypeScript；
- 后端：FastAPI + Pydantic；
- 数据库：PostgreSQL；
- 检索：PostgreSQL全文检索与 pgvector；
- 文件：兼容S3/OSS的对象存储；
- AI：大语言模型、Embedding、可控工具调用；
- 任务：异步任务队列用于文档处理与长耗时Agent流程；
- 工程：Docker、自动化测试、CI、日志与指标。

## 7. 团队分工

### 产品负责人 / AI集成

- 需求、Agent工作流、RAG评测和系统集成；
- GitHub维护、PR审查、演示与答辩。

### 前端 / UI

- 使用Stitch完成Web端设计；
- 实现设备中心、诊断工作台、工单和看板；
- 负责响应式适配和演示体验。

### 数据库 / 后端

- ER图、数据库迁移、API与权限；
- 设备、工单、备件和审计数据模型；
- 自动化测试与性能检查。

### 指导老师

- 审核数据库与制造业务模型；
- 指导企业需求、数据治理和系统集成；
- 协助获取脱敏案例和企业反馈。

## 8. 里程碑

### M1：工程与数据库基线

- 前后端工程、Docker和CI；
- 用户、企业、设备和参数模型；
- 设备档案基础CRUD。

### M2：文档知识库

- PDF入库、分块、索引和检索；
- 带来源引用的设备问答；
- 建立小型评测集。

### M3：Agent与工单闭环

- Agent受控调用设备、检索和工单工具；
- 诊断建议转工单；
- 工单结果回写维修知识。

### M4：比赛完成度

- 完成Stitch UI落地、异常处理和权限；
- 准备脱敏演示数据、录屏、架构图和答辩材料；
- 完成部署、测试报告和性能数据。

## 9. MVP验收标准

- 用户能选择一台设备并提出问题；
- 回答同时检索设备参数、说明书和维修历史；
- 每个关键结论能查看来源；
- 用户确认后可生成维护工单；
- 工单处理结果能回到设备历史中；
- 不同企业的数据不可相互访问；
- 模型不可用时给出明确错误，不伪造成功结果。

## 10. 演示案例

以“电机温度异常”为例：用户进入电机档案并提问，Agent查询额定参数、说明书和历史工单，给出按风险排序的检查步骤和证据；用户确认后创建工单，维修人员记录根因与更换的备件，完成结果自动关联设备并成为下一次检索的案例。
