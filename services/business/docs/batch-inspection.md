# 人工巡检批量接口

本接口用于一次提交同一设备的多个人工巡检指标。参数和审计记录在同一数据库事务中写入，全部成功才返回 201；任一指标非法、重复或写入失败时整批不保存。无需数据库迁移，旧的单项参数接口保持兼容。

## 请求

`POST /api/v1/devices/{device_id}/parameters/batch`

使用现有 Bearer 身份认证，角色至少为 technician。设备编号属于当前组织；设备不存在、已软删除或属于其他组织时返回 404。

```json
{
  "recordedAt": "2026-11-11T14:30:00+08:00",
  "sourceRef": "人工巡检：驱动端轴承",
  "items": [
    {"name": "vibration", "value": 3.2, "unit": "mm/s"},
    {"name": "temperature", "value": 76.5, "unit": "°C"}
  ]
}
```

- `recordedAt` 必填且包含时区；服务端转换为 UTC。整批使用同一采样时间，避免重试时生成新时间而重复保存。
- `sourceRef` 必填，去除首尾空白后为 1–255 个字符，记录实际测点位置或人工巡检来源。
- `items` 为 1–100 项，按输入顺序返回。`name` 去除首尾空白后为 1–120 个字符，同一请求内不能重复；名称区分大小写，与旧接口一致。
- `value` 必须为有限数，最多 18 位有效数字、小数部分最多 6 位、整数部分最多 12 位，与数据库 `Numeric(18, 6)` 一致。允许负数，不在接口中猜测各指标的工程范围。
- `unit` 可选，最多 32 个字符。每项只接受 name、value、unit；顶层只接受 recordedAt、sourceRef、items，不接受客户端指定组织、操作人、source 或权威标记。
- 所有记录固定为 `source=manual`、`isAuthoritative=true`，表示人工采集来源，并不代表设备无故障或最终诊断结论。

## 成功响应

状态码 201。响应为 `{"batchId":"UUID", "items":[参数对象], "total":2}`。每个参数对象沿用单项接口字段：id、deviceId、name、value、unit、source、sourceRef、isAuthoritative、recordedAt、createdAt。

每个指标产生一条 `device_parameter.create` 审计，包含当前组织、操作人、参数 ID、设备编号、测点来源、采样时间和共享的 `batchId`。审计与参数一起提交或回滚。

## 失败与重试

| 状态码 | 条件 | 写入结果 |
|---|---|---|
| 401 | 现有认证规则拒绝身份 | 无写入 |
| 403 | 当前角色低于 technician | 无写入 |
| 404 | 当前组织查不到设备 | 无写入 |
| 422 | 空批次、超量、重复指标、非法数值、无时区时间、空测点等 | 无写入 |
| 409 | 同设备、同指标、同采样时间已有有效记录，或并发写入触发唯一约束 | 整批回滚 |
| 500 | 非预期数据库或审计写入故障 | 整批回滚，不返回部分成功 |

重复请求明确返回 409，而不是返回先前的 201。该接口提供重复写入保护，不提供请求结果重放。超时后应先读取 `GET /api/v1/devices/{device_id}/parameters` 核对记录，再决定是否重试；重试必须保持原采样时间。改变采样时间表示新的巡检。有效记录唯一约束继续使用现有索引，软删除的记录不参与去重。

旧单项新增和更新接口仍允许原有请求结构；本轮将其中带时区的新输入也转换为 UTC，以便与批量接口交替使用时正确识别同一时刻。旧单项接口继续接受无时区时间。已有 SQLite 历史行未作迁移；如果旧程序曾把非 UTC 偏移时间直接存为无时区值，需要另外核对原始时区，不能据此推断历史时间已修正。

## 前端交接

现有 `buildInspectionPayloads` 产出逐项数组。接线时将共有 recordedAt、sourceRef 提到请求顶层，items 仅保留 name、value、unit，并只发送一次请求。收到 201 后整体刷新；409/422 或其他错误时保留表单内容并展示错误，避免循环调用旧单项接口造成部分保存。前端接线由产品集成分工完成。

## 验证

在 `services/business` 运行 `python -m pytest -q` 和 `python -m ruff check .`。

`tests/test_batch_inspection.py` 覆盖全成功、非法项全失败、权限与组织隔离、UTC 时区归一、重复请求、已有记录冲突、唯一约束竞争、写入中途审计故障及新采样时间。唯一约束测试跳过预检查以触发真实数据库冲突；回滚检查均从新 Session 查询参数与审计数量。

本改动仅供候选分支审查，不包含线上部署、数据库迁移、main 合并或前端修改。
